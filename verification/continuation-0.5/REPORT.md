# Продолжение исследований · Platform Studio 0.5

Дата: 18 ноября 2026 года. Продолжение существующего кода после `8ad7b3d`; исходная линия `3967b46` сохранена. Этот инкремент закрывает конкретную стыковку W4 и добавляет проверки W0. Полная приёмка ТЗ не объявляется.

## Изменённое поведение

- `thread/start` и `thread/resume` получают сохранённую память задачи из TaskStore автоматически. В ней точная текущая цель, редакции, ограничения и счётчики, статус исследования, ссылки на отчёты, выбранные наблюдения, отрицательные/неполные свидетельства и неизвестные исходы. Дополнительный вызов модели не требуется.
- Собственный пакет продолжения ограничен **12 288 байт UTF-8**. Полная история разговора, полные журналы и параметры прежних команд в него не копируются. Пропуски подробностей перечисляются явно; адреса и хэши исходных отчётов сохраняются. Обязательные сведения не обрезаются: превышение предела останавливает подключение до запуска процесса и записи внешней команды.
- Точные параметры отправки сохраняются прежним outbox. Повторное обращение с тем же command ID читает прежний результат и не пересобирает запрос из изменившейся памяти.
- Assistant Desk показывает размер и содержимое пакета. Действие «Новая сессия с результатами» создаёт тред той же задачи, сохраняет счётчики и историю, не отправляет ход автоматически. Прежние сессии доступны через выбор в задаче; черновик сохраняется.
- Проверка перед новым тредом/ходом учитывает другие сессии задачи, включая старые неразрешённые команды за пределами последних 1000 записей. После потери ответа интерфейс открывает сессию сохранённой команды, а не отправляет новую. Подтверждённый незавершённый ход остаётся `state_unknown` после отключения/перезапуска до авторитетной сверки. Поздний отчёт прежней цели не вытесняет checkpoint текущей редакции.
- Набор реальных stdio-тестов проверяет разорванные JSON/UTF-8 кадры, поздний ACK, смерть дочернего процесса после отправки и завершение хода до получения ACK.

## Проверки без обращения к модели

Локально прошли **375/375 Node-проверок** и **71/71 Rust-проверок** (25 core, 12 recovery, 34 host). В host входят 16 новых проверок продолжения и 8 проверок настоящих stdio pipes. Сводки: `node-tests.json`, `rust-tests.json`. Проверка интерфейса — DOM-стенд, без запуска GUI.


Локальные команды:

```sh
npm run verify
cargo test --manifest-path native/Cargo.toml --locked -p studio-core -p studio-host
node scripts/probe-codex.mjs --codex /absolute/native/codex --out /absolute/evidence
```

PowerShell для уже установленного Codex:

```powershell
./scripts/Probe-Codex.ps1 -CodexExe 'C:\absolute\codex.exe' -OutDirectory 'C:\absolute\evidence'
```

Скрипт не устанавливает Codex на пользовательский ПК, не открывает GUI, не читает пользовательский профиль и не отправляет `turn/start`. Node нужен только этому скрипту разработки/CI; он не добавлен в runtime приложения. Код завершения `0` означает прохождение проверяемого сценария либо точное наблюдение ожидаемых предусловий (различается в report.status; ACK resume указывается отдельно), `2` — недоступность среды/политики, `1` — нарушение проверяемого условия.

На локальном Codex **0.167.0-alpha.4** прошла инициализация. Восемь используемых форм параметров совпали с локально сгенерированной stable-схемой. `thread/start` остановился на `bwrap: NETLINK_ROUTE: Operation not permitted`; обхода sandbox нет. Поэтому Linux-результат — **metadata-unavailable**, не успешный сценарий треда. Запросов к endpoint модели: **0**, отправленных `turn/start`: **0**. Доказательства находятся в `codex-linux/`.

Первый Windows-прогон настоящего Codex **0.170.0** (`44280377330`) прошёл initialize, thread/start и thread/read, затем обнаружил семантическую несовместимость: до первого сообщения `thread/turns/list` возвращает `-32600` с явным признаком нематериализованного треда. Это ломало и сверку production-клиента сразу после подключения; ошибка не скрыта и сохранена в `codex-windows-first/`. Исправлена обработка только подтверждённого пустого треда: точный RPC-код/текст и ID, авторитетные idle + turns=[], отсутствие известного локального хода. Результат явно сообщает historyAvailable=false; неизвестные отправки не подтверждаются и не повторяются. Модельный ход для создания истории не запускается.

CI использует отдельный Windows-прогон официального Codex **0.170.0**: закреплены версия, URL и SHA-256 архива. Загрузка происходит только на одноразовом CI runner. Отказы не маскируются успешной приёмкой; точный результат сохраняется как `codex-windows-protocol-evidence`.

## Границы результата и подтверждённые остатки

1. **12 КиБ — предел добавленного нами пакета, а не полного запроса Codex.** Фактическое снижение токенов, числа модельных ходов и времени решения ещё требует парного испытания W5. «300%» не измерено и не заявлено.
2. `freshness` обозначает совпадение редакции цели. Файлы при сборке пакета не перечитываются; `sourceFreshness: not-rechecked` указан явно. Хэш сохранённого отчёта не доказывает актуальность текущего исходника или правильность причинного вывода.
3. **Предварительный допуск MCP `diagnostic_sweep` ещё отличается от native `research_sweep`.** Native-маршрут проверяет TaskStore до исполнения; MCP observer импортирует результат после исполнения. Передача стоп-правил в контекст не исправляет этот разрыв принудительного контроля.
4. **Профиль добавляет локальный MCP, но не отключает унаследованные MCP автоматически.** Это воспроизведено на собственном тестовом профиле: даже корневой override таблицы сохраняет ранее включённый сервер. Гарантия «только локальные инструменты» пока не принята; пользовательская конфигурация не изменялась.
5. Native-сохранение содержательных `Finding` пока не подключено. Сохраняются наблюдения инструментов и планы; смысловые выводы не должны объявляться проверенными только из-за успешного чтения. Полный семантический руководитель остаётся отдельным пунктом.
6. Потерянный ответ `thread/start` без известного `threadId` сохраняется как неопределённость. Автоповтора нет; удобное подтверждённое разрешение этого случая владельцем ещё не реализовано. Межпроцессная блокировка допуска задачи при двух отдельных экземплярах Director также не добавлена.
7. CLI/DOM-стенды и Windows-компиляция не заменяют приёмку GUI, полного пользовательского сценария и изоляции G1/G2/G3. Запросы к реальной модели в этом инкременте не выполняются.

Следующие работы остаются в принятом плане: допуск MCP до выполнения через существующий хост, сохранение интерпретации с основаниями в TaskStore, затем проверка качества и расхода на фиксированных задачах. Новый inference backend, второй оркестратор или дополнительный сервис не добавлены.
