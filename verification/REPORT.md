## Что именно проверяли отрицательные случаи

Сохранение send-fence до транспорта; невозможность отправки после отказа записи; один выигравший CAS при двух клиентах; changed intent с тем же ID; потерянный ACK; пустая readback-страница; совпадение в чужом треде; отражённый моделью nonce; неоднозначные элементы; позднее подтверждение; запрещённый сброс unknown; tombstone против запоздалого IPC; независимость task/session; неизменяемая история цели; неподдержанная IPC-команда; смешение сессий при projection; фактические и неизвестные метрики; сохраняемый черновик; согласие до rerender; отсутствие auto-dispatch при boot и polling.

## Нативная ветка: написано, но НЕ выполнено

**36 Rust-тестов** (прежние 26 и 10 новых). Среди новых — actual Store restart/fence, goal CAS, completion-before-ACK, старое поколение, task-level запись и event accounting, плюс framing. Они ожидают сборки. Ни один не записан в число 305.

В среде отсутствуют `cargo`, `rustc`, `pwsh`, `codex`. Windows недоступна. Rust/Tauri не компилировались. Cargo.lock не создан. API-совместимость crate pins, native sqlite, named pipe, Win32 и App Server не проверена. Готовых EXE/MSI/установщика нет.

Node SQLite на стенде — **3.49.1, rollback journal**. Целевой Rust Store по-прежнему требует **SQLite >=3.51.3** перед WAL. Запрет не ослаблялся ради тестов. Эти испытания не устанавливают свойства Windows/WAL/NTFS при отказе питания.

## Неподтверждённые пользовательские возможности

Не было живого перевода поручения, semantic supervisor, Codex usage владельца, фактического steer/interrupt, принудительного перезапуска оболочки Windows, проверки реальных многовкладочных гонок, файловой приёмки/публикации, GUI/браузера/dev-server/Computer Use. Внешние модели, их API, платные запросы и секреты не использовались.

Состояние G0-08 хранится у задачи, а не новой сессии. Однако автоматическая квалификация независимого свидетельства и host-accounting расхода ещё не включены. Успешные tool calls не сбрасывают счётчик по умолчанию. Нет заявления о жёстком токеновом или финансовом потолке.

## Ограничения Direct-профиля

Первый источник содержит только read-only исполнение; запись в проект и независимая проверка не закрыты. Постоянные настройки Codex не редактируются. Параметры отключения Computer Use добавлены, но конкретная версия, hooks/MCP, shell и права должны быть приняты отдельной целевой проверкой. Плашка read-only не доказывает запрета запуска GUI или чтения всех соседних путей.

UI читает ограниченный журнал с курсором. Это не lossless-журнал всех инструментов и не полная телеметрия ОС. Секреты в произвольном выводе не гарантированно отредактированы; полная БД остаётся приватной. История после restart отображает сохранённое/прочитанное и обозначает пробелы; потерянные streaming-дельты не реконструируются выдуманными событиями.
