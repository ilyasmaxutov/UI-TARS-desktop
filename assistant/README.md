# Помощник · Assistant Desk 0.1

**Это интерактивная реализация экранов и сценариев + реальный локальный анализатор журналов. Не готовый автономный агент и не новая версия универсальной площадки.**

## Открыть экраны

Откройте `dist/Assistant_Desk.html` вручную. Интернет, npm и сервер не нужны.

Шесть рабочих поверхностей: работа; оригинал и английское поручение; изменения и принятие; наблюдение; команда на двух листах; подключения.

Кнопка «12 сценариев» открывает нормальный путь и конфликтные состояния. Сценарные данные явно помечены. Нет таймеров, которые выдают анимацию за работу модели. Принятие не публикует файл. Состояния модели проверяются отдельно от качества настоящей модели.

Редактирование и экспорт задания, локальное сохранение черновиков, адресованные замечания и импорт журналов работают в коде. Хранилище браузера зависит от среды открытия `file://`; при запрете или конфликте предлагается экспорт, а не молчаливое «сохранено».

## Получить метрики своего Codex сейчас

### Без скриптов

Откройте «Наблюдение» → «Импорт журналов». Выберите `rollout-*.jsonl` из вашего профиля Codex. Обычный путь — `%USERPROFILE%\.codex\sessions`, либо путь внутри выбранного `CODEX_HOME`. Можно импортировать несколько файлов. Ограничения: 64 МиБ/файл, 128 МиБ суммарно, 200 000 событий. Большая история требует отдельных выборок. Данные не отправляются в сеть.

### Со сборщиком Windows

В распакованной папке, в **PowerShell 7.5 или новее**:

```powershell
.\tools\Collect-Codex.ps1 -Watch
```

Один снимок, без постоянного наблюдения:

```powershell
.\tools\Collect-Codex.ps1
```

Другой профиль:

```powershell
.\tools\Collect-Codex.ps1 -CodexHome 'C:\Users\USER\.codex-work' -Watch
```

Сборщик создаёт `Codex-Observation\capture-…\capture.json` и `Report.html`. Откройте `Report.html` вручную. Для следующего снимка обновите страницу. Закройте сборщик через Ctrl+C. Он не устанавливает службу, не стартует вместе с Windows, не запускает Codex/браузер и не изменяет конфигурацию. Выполнение политики PowerShell не обходится; если Windows блокирует скачанный скрипт, не отключайте глобальную защиту вслепую: остаётся прямой импорт JSONL.

По умолчанию выбираются 50 недавно изменённых файлов за последние 7 дней, до 32 МиБ на файл и 50 000 событий. Выбор идёт по времени изменения файла, НЕ по времени каждого события. Первая точка расхода может относиться к более ранней работе. Неизменившиеся файлы кешируются, изменившиеся перечитываются в пределах лимита. Это не малозатратный бесконечный tail всех файлов. ZIP/ZST, ссылки и неподдержанные поверхности явно пропускаются. Пропуски перечислены в capture.

**PowerShell-сборщик здесь не запускался.** На стенде нет PowerShell/Windows. Рабочий JS-анализатор проверен отдельно и доступен через прямой импорт. Целевой сквозной Windows-прогон остаётся открытым.

## Что означает отчёт

- `input`, `cached`, `output`, `reasoning`, `total` — раздельные счётчики. Кеш не прибавляется к input второй раз; reasoning не прибавляется к output повторно.
- Новые `token_usage_record` объединяются по `response_id`, без повторного прибавления `token_count`.
- Для старых накопительных счётчиков считаются наблюдённые приращения. Первая точка — исходная база, не расход выбранного интервала. Сброс и наследование ветви показываются отдельно.
- Длительность хода и объединённый интервал инструментов вычисляются по наблюдённым границам. Нет конца — нет выдуманной длительности.
- `time_to_first_token_ms`, когда он присутствует, показывается как **сообщённый Codex TTFT**. Время до первой видимой дельты/полного сообщения — другой показатель. Из него не выводятся сеть, серверная очередь или «скорость мышления».
- Проценты `rate_limits` показываются только при наличии события. Из токенов не выводятся цена, оставшиеся деньги или процент подписки. Одновременная другая сессия может менять общую квоту.
- Число ходов не выдаётся за число API-запросов. Количество ответов доступно лишь по соответствующим response_id.
- Отчёт покрывает только прочитанные события. Он не видит все действия ОС, сетевые пакеты, внутреннюю очередь сервера и не восстанавливает удалённые/неписавшиеся логи.

Выбранный сырой JSONL может содержать приватный код, команды и разговоры. Анализатор и сборщик сохраняют только разрешённые поля метаданных; не считайте исходный JSONL безопасным для публикации. В экспорт не попадают аргументы команд, ответы, промпты, cwd и auth.json. Идентификаторы сессий и имена моделей остаются: это не анонимизация.

## Проверка исходников (не требуется для использования HTML)

Node 22 без сторонних пакетов:

```powershell
node --test tests/*.test.cjs
node tools/build.mjs
node tools/Analyze-Codex.mjs .\fixtures\synthetic-rollout.jsonl --output .\new-report.json
```

CLI откажется перезаписывать существующий файл отчёта. Исходный журнал только читается.
