# Разделение: помощник и исполнительная служба
Дата: 9 ноября 2026. Проектное решение по новому уточнению владельца; не заявление о принятой полной платформе.

## Что изменено
Прежние Platform Studio 0.1/0.2 и ТЗ сохранены, не перезаписаны. Их G1/G2 относятся к заявляемой собственной изолированной площадке. Они не являются необходимым условием чтения журналов, составления поручений и испытания пользовательских сценариев помощника. Более сильные гарантии исполнения нельзя объявлять выполненными без их приёмки.

**Продукт A: приложение помощника.** Владеет целью, пониманием намерения, версиями поручений, контекстом проекта, решениями надзора, комментариями и результатами. Может само выполнять разрешённую работу через тот же исполнительный интерфейс, а не только делегировать. UX: запрос → правильное поручение → выполнение/вмешательство → проверка → результат. Конструктор — дополнительное представление, не обязательный вход.

**Продукт B: исполнительная служба.** Владеет жизненным циклом сессии, ограниченными файловыми/CLI/API-операциями, событиями, разрешениями, наблюдением, снимками и восстановлением. Не «понимает цель» вместо A и не публикует результат потому, что модель назвала его хорошим. Не обязан поддержать все модальности и потоки ради первой интеграции Codex.

Для пользователя это один установленный помощник. Отдельный инженерный продукт B имеет свой процесс, контракт и тесты, но не навязывает второй ежедневный интерфейс. Проекты, модели, инструменты и любые операции не становятся отдельными административными разделами только потому, что они есть в базе.

## Первый живой профиль — без собственного универсального движка
Готовый Codex harness — первый допустимый исполнитель. Адаптер использует штатные thread/start/resume, turn/start/steer/interrupt и события. Не переписывает вручную JSONL/SQLite Codex, не захватывает его UI, не извлекает ключи и не подставляет bypass. Подключение/продолжение существующего thread проверяется на фактическом профиле; другой аккаунт или другой ChatGPT-чат не считаются тем же объектом.

По умолчанию технические исследования начинаются с read-only/метаданных. Переход к записи требует отдельного допуска, рабочей версии и применимой гарантии sandbox. Git worktree сам по себе не граница безопасности. Отсутствие собственного GPU-пула не блокирует работу с удалённым Codex.

## Небольшой контракт службы
1. `capabilities`: фактически доступные операции, версия, профиль доверия, покрытие наблюдения.
2. `sessions.list/read`: обнаружение доступных сессий без автоматического продолжения.
3. `turn.start/resume/steer/interrupt`: адресованные операции с ID команды, известным состоянием и сверкой.
4. `events.read/subscribe`: временные метки, происхождение и пробелы; не обещание полной трассы ОС.
5. `project.read/snapshot/diff`: разрешённая область, версия чтения, отдельное предложение.
6. `tools.invoke`: только зарегистрированная разрешённая CLI/API/файловая операция. Сам помощник — такой же клиент.
7. `result.review/publish`: доказательства и явное решение по конкретному снимку, конфликт не затирается.

Не нужны до этой вертикали: универсальный планировщик распределённых вычислений, собственный inference manager, весь медиаграф, много аккаунтов с ротацией, маркетплейс, внешние чаты всех поставщиков. Эти функции остаются в отдельном будущем объёме B; текущий отказ от их преждевременной разработки не снимает ограничений безопасности первой операции.

## Следующие задания исполнителям: четыре узких пакета

| Пакет | Что реализовать | Приёмка, которая не зависит от отчёта агента |
|---|---|---|
| A1 · Реальное наблюдение | Прогнать сборщик на Windows-копии профиля; проверить версию формата и все лимиты | Без доступа к auth.json; одинаковые метрики ручного fixture и отчёта; исходные bytes не изменены; неполный хвост виден |
| A2 · Адаптер одной сессии | handshake, list/read, new thread и explicit resume, журнал команды и read-only сверка | Один нужный thread; потеря ACK не даёт второй turn/start; старая expectedTurnId отвергнута; без provider call для list/read сверх семантики реального harness |
| A3 · Поручение и надзор | Отдельная роль преобразует RU-цель в EN-поручение; валидатор покрытия; одна итерация корректировки | Нельзя выкинуть обязательный запрет; ложный успех возвращается; положительный результат принимается в своей области; prompt/evidence/limitations доступны в тех же экранах |
| A4 · Файловое предложение | Снимок базы, разрешённый diff, комментарий, повторная проверка, безопасное применение | Ручная правка сохраняется; старое заключение не принимает новый diff; ограниченный result выходит в нужный проект |

Пользователь не обязан писать этим пакетам инструкции. Исполнитель использует интерфейс, контракт, фикстуры и коллизии этого пакета; недостающие решения формулирует сам и предъявляет только существенную развилку. Критерии не переписываются ради зелёного теста. Производственные вызовы и изменение пользовательского ПК не выполняются в данной сессии.
