# Опциональный допуск модельных запросов

**Статус: работающий ограниченный HTTP/SSE-компонент, испытан с локальным тестовым сервером. Не принят как полный перехватчик Codex или подписочного трафика.** По умолчанию выключен; самостоятельный `launch` его не включает.

## Реализовано

Один явно выбранный HTTPS upstream, один устойчивый task ID. Только POST /responses. Нет агента, inference loop, новой модели, маршрутизатора, выбора аккаунтов и авторизации из файлов. Authorization пересылается только выбранному адресату и не записывается в журнал.

До сетевой отправки проверяются: размер тела; разрешённые поля; полный доступный явный текст входа/инструкций/описаний функций; количество запросов по задаче. Начальные пределы: 192 КиБ JSON, 48 000 **client units**, резерв 4096 units для служебной части, максимум 8 отправок, ответ до 16 МиБ. Client units — консервативная сумма видимого UTF-8 и заданного запаса, **не точный токенизатор и не формула оплаты**. JSON канонизируется до проверки и отправки, чтобы получатель не получил другое толкование дублирующихся ключей.

Неизвестная/скрытая история (`previous_response_id`, conversation, hosted prompt), изображения/аудио/файлы, server-side tools, WebSocket и нераспознанные поля закрыты. Непрозрачный `encrypted_content` по умолчанию также закрыт: нельзя доказать размер скрытого входа по длине шифротекста. Тестовый режим привязки ранее наблюдённого encrypted item не включён в CLI-профиль.

**Следствие:** часть настоящих reasoning/multi-turn запросов будет отклонена. Это не готовый прозрачный пропуск всех моделей Codex. Приложение не объявляет настройку зелёной и не переключает подписочный endpoint ради обхода этого ограничения.

Перед отправкой fsync намерения; после обрыва — unknown без повтора. При unknown новая отправка той же задачи также блокируется. Запрос с тем же fingerprint не проходит повторно после перезапуска. Volatile metadata не позволяет обойти дедупликацию. История расхода привязана к task, её нельзя сбросить сменой policy/upstream. Новый task — действительно новая единица бюджета; глобальное наследование всех детей платформы не реализовано.

Ответ сохраняется локально. Если отключился клиент, компонент продолжает ограниченный приём уже отправленного ответа; reconnect интерфейса не делает второй модельный запрос. Если оборвался upstream, сохраняются частичные байты и unknown. Нет переключения на HTTP/аккаунт/модель, скрытых ретраев, 429-циклов или следования редиректу.

Привязка к OS-сети не принуждается: процесс, обращающийся прямо к провайдеру, обходит этот компонент. Нет доказанного верхнего денежного/подписочного расхода; полученные usage-счётчики — отдельные наблюдения. Реальный провайдер не вызывался.

## Ручной исследовательский профиль

```powershell
.\studio-economy.exe gate --project 'C:\Dev\Project' --task 'real-task-001' --upstream 'https://YOUR-EXPLICIT-PROVIDER/v1' --max-requests 8
```

Это пример для владельца, сознательно подключающего известный Responses-совместимый endpoint; строка не является действующим адресом и не указывает подписочный ChatGPT-маршрут. Команда только запускает локальный listener и не вызывает модель. Выданный local baseUrl содержит случайный capability token: не публикуйте его. Соединение только numeric loopback, браузерные Origin-запросы отклоняются.

Автоматическая запись этого URL в пользовательский config отсутствует. Нет команды автоматического снятия unknown: сначала требуется сверка с реальным получателем. Для первого инструмента экономии используйте обычный `launch` с локальными пакетами, не пытайтесь сделать эту экспериментальную часть обязательной предпосылкой.

## Что доказывают тесты

Получатель-фикстура наблюдает 0 отправок для слишком большого/неизвестного входа; одну — для допустимого; после повторной доставки/обрыва/рестарта нет второго эффекта. Проверены конкурентные отправки при остатке 1, частичный SSE, потеря ACK, redirect, 429, gzip, сохранение частичного ответа, отказ хранилища и политика, переживающая restart. Это протокольные и файловые свойства, не испытание настоящего Codex и не A/B экономии токенов.
