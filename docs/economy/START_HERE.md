# Экономия · поставка 0.4

В пакете есть готовый `studio-economy.exe` для Windows x64. Это локальный помощник инструментов, а не вторая модель. Python, Node, Go, Rust, Docker и установка службы для работы EXE не нужны. **Сам установленный Codex нужен только для команды `launch`.**

## Начало

Распакуйте пакет в постоянную папку. В PowerShell этой папки:

```powershell
.\studio-economy.exe selftest
.\studio-economy.exe launch --project 'C:\Dev\MyProject'
```

Первая команда выполняет локальный опыт на собственных временных файлах; сеть и модель не вызываются. Она выводит путь к JSON-отчёту. Вторая **явно запускает ваш Codex**, после чего можно писать обычную задачу. Она не устанавливает Codex, не меняет глобальный `config.toml`, не открывает браузер входа и не заменяет аккаунт. Нативный EXE ищется в PATH и типичных каталогах уже установленного npm-пакета; при неоднозначности нужно явно указать `--codex 'C:\...\codex.exe'`. CMD/PowerShell-обёртка не исполняется.

Альтернатива — `Start-Economy.ps1`: он спросит только папку проекта. Скрипт не меняет ExecutionPolicy. Если политика запрещает скрипт, используйте команду EXE выше; обходить политику не нужно.

**Важно:** EXE скомпилирован для Windows, но выполненные разработчиком проверки проведены на Linux. Windows-прогон и реальный установленный Codex ещё не проверены. Бинарник не подписан; SHA-256 приложен. Не отключайте антивирус ради запуска.

## Что подключается к Codex

Два локальных MCP-инструмента:

- `local_batch`: до 32 операций. Поиск, несколько диапазонов чтения, чтение найденных мест, метаданные, хэши, Git status/diff, проверка из отдельно утверждённого списка, чтение сохранённого лога. Между операциями модель не вызывается.
- `context_pack`: исходная цель, обязательные правила и выбранные **точные** материалы. Если они не помещаются, ошибка, а не тихое выбрасывание ограничения.

Результат пакета ограничен **24 КиБ вместе с JSON-оболочкой MCP**, обычное поле текста — 4 КиБ. Это байты, не токены. Полные разрешённые результаты лежат вне проекта. Ссылки на них остаются в ответе; можно дочитать диапазон, найти строку или прочитать байтовый срез. Важная ошибка в середине большого лога не требует повторного запуска команды.

`search` принимает буквальный запрос, не регулярное выражение. `read_matches` ссылается на `id` предыдущего поиска через `from`. Это позволяет одним пакетом найти и прочитать места без промежуточного модельного запроса.

Настройки запуска отключают встроенный shell, веб-поиск, автоматическое размножение агентов и память; задают ориентир 6000 токенов для одного ответа инструмента/пакета и небольшие ориентиры контекста. Автоматический recap TUI отключён. Codex может дополнительно усекать результат по собственным правилам; полнота модельного представления требует проверки на конкретной версии. Поэтому пакет сохраняет адресуемые локальные оригиналы, а для плотного дампа следует запрашивать небольшие диапазоны. Пакет не удаляет AGENTS.md и не отключает защитные hooks. Существующие сторонние MCP/hooks остаются отдельной областью настройки и могут иметь собственное поведение. Возможность конкретных ключей должна подтверждаться установленной версией Codex.

**Цена ограничения:** в этом профиле нет произвольного shell, поэтому произвольная сборка/установка/команда не исполняются по желанию модели. Для проверок служит утверждённый владельцем список; обычная поставка включает только чтение и фиксированные Git-операции. Это намеренно ограниченный инструмент исследования, а не обещание полной автономной разработки.

## Локально, вообще без Codex

```powershell
.\studio-economy.exe run --project 'C:\Dev\MyProject' --input .\examples\search-read.json
```

Результат — один JSON с отдельными статусами, ссылками на полные материалы и известными ограничениями поиска. Для новой работы меняйте `id` пакета; тот же ID возвращает старый снимок и не повторяет успешно выполненные элементы. Это защищает от дубля, но не означает свежесть старого снимка.

Проверка большого вывода:

```powershell
.\studio-economy.exe demo --output '.\new-local-evidence'
```

Каталог должен отсутствовать. Опыт создаёт 20 маленьких источников и **100 МиБ** собственного stdout, ищет ошибку из середины, проверяет повторное чтение пакета и локальный отказ слишком большого запроса. Это реальные локальные операции, но не измерение экономии квоты модели.

## Хранение и ограничения

По умолчанию: `%LOCALAPPDATA%\PlatformStudio\economy\<ключ проекта>`. Артефакты и журналы приватны по назначению, не добавляются в рабочий проект. На Windows права наследуются от профиля пользователя: EXE **не создаёт границу от других процессов того же пользователя**. Содержимое не отправляется автоматически, но может содержать секреты; универсального редактирования секретов нет.

Лимиты: до 4 параллельных чтений, 64 КиБ на диапазон, 32 МиБ обследованного текста и 2000 файлов на обзор, 128 МиБ захвата команды, 512 МиБ учёта хранилища. Известные generated/vendor-каталоги исключены из обзора; при необходимости есть явный `includeGenerated`. Исключение не равно доказательству отсутствия материала. Ограничение логов видно в `captureComplete` и `reason`, код завершения не подменяется. Повтор с неизвестным исходом сам не запускается.

Хранилище не чистится автоматически и не удаляет историю ради экономии. При заполнении операция останавливается с причиной. Ротация/выборочное архивирование через GUI не реализованы. Конкурирующие процессы одного пакета блокируются; общий дисковый предел не является квотой Windows для всех возможных внешних писателей.

Переходы по ссылкам и обычный выход за корень запрещены, но это **не AppContainer**. Утверждённая программа может совершать действия вне файлового корня. Не добавляйте недоверенный executable в список проверок.

## Что не гарантируется

`launch` не устанавливает жёсткий предел каждого внутреннего запроса штатного Codex и не гарантирует процент экономии подписки. `model_context_window` и порог компактизации здесь не выданы за такой запрет. Нет фоновой модели-сжимателя, перехвата вашего аккаунта или скрытого платного теста.

В том же EXE есть **отдельный экспериментальный HTTP/SSE-допуск `gate`**: запрет большого явного запроса и числа отправок до сети, сохранение ответа, отсутствие автоматических повторов. Он не включается молча вместо подписочного маршрута. Его контракт и ограничения — в `REQUEST_GATE.md`. Полная совместимость с reasoning/history Codex и глобальный контроль трафика **не приняты**.

## Источники и проверка

Исходники: `native/tools/economy/`, стандартная библиотека Go, внешних модулей нет. Нативная интеграция Studio: `native/crates/host/src/codex/economy.rs`. Её Rust-сборка остаётся непроверенной. Сценарий использования EXE не зависит от этой сборки.

## Разрешённая проверка без свободного shell

Дополнительно владелец может создать JSON **вне проекта** с именованными командами. Пример формы:

```json
{"verify":{"program":"C:\\Program Files\\PowerShell\\7\\pwsh.exe","args":["-NoProfile","-NonInteractive","-File","scripts\\Verify.ps1"],"timeoutSeconds":120}}
```

Пути и скрипт должны реально существовать и быть проверены владельцем. Пример ничего не устанавливает и сам не исполняется. Запуск:

```powershell
.\studio-economy.exe launch --project 'C:\Dev\MyProject' --checks 'C:\Private\approved-checks.json'
```

После этого модель может вызвать `{"id":"v1","op":"check","check":"verify"}` внутри пакета. Она не может передать произвольный executable/аргументы в этот инструмент. Полный вывод и настоящий exit code сохраняются. Это согласие на **содержимое указанного executable/скрипта**, не OS sandbox: программа сама может выполнять другие действия. В native Studio Direct-профиле такой список из UI пока не подключён.
