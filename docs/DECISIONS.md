# Реализаторские решения инкремента 0.1

## ADR-I01 · Не подменять исполнение анимацией

Доступный встроенный узел получает реальные входы, возвращает вычисленный выход и проверяется. Статусы выводятся из событий исполнителя. Узел Codex блокирует preflight; красивый макет команды не получает «готово».

## ADR-I02 · Два явно различных профиля

1. `browser-local`: исполняемые встроенные операции в Web Worker. Исходники импортируются как текстовые копии. Это работает без установленного native backend, но не является границей Windows, не поддерживает недоверенные бинарники и не обещает работу закрытой вкладки.
2. `native-builtins`: Rust-исходники с отдельным Windows-хостом и SQLite. Код подготовлен, но не собран на данном стенде. Недоверенные процессы и внешние агенты всё равно закрыты.

Профиль проверенного OS containment отсутствует. Его нельзя заменить наличием Web Worker, отдельного процесса или хэша. Ворота G1/G2 остаются открытыми.

## ADR-I03 · Начальный renderer без React Flow

План 3.0/3.1 предполагал React + React Flow. В доступном стенде нет этих пакетов и доступа к registry. Чтобы предъявить проверяемое исполнение и редактируемый продукт, начальный renderer написан на TypeScript DOM/SVG без внешних библиотек. Это явное отклонение, не утверждение эквивалентности React Flow. Контракты semantic graph, run, view и storage не зависят от renderer. Замена сохраняет импорт и идентичности.

В этой реализации SVG используется только для связей, DOM — для карточек. Нет заявленного прохождения профиля 500/1000 узлов/связей; virtualization, semantic zoom и частичные подписки ещё нужны. Во время событий текущий UI перерисовывает карточки и отдельные панели: это необходимо оптимизировать и измерить.

## ADR-I04 · Полезный узкий набор вместо фиктивной универсальности

Доступны конечные DAG с `text`/`files` и правилом `all-once` для merge. Циклы, условные маршруты, динамические плагины, потоки и частичные запуски остаются открыты. Сохранённые примитивы event-time/queue отдельно проверены, но не являются готовым медиа-runtime.

## ADR-I05 · Критерий, целостность и принятие различны

Исходная цель и критерии заморожены вместе с запуском. Финальный выход проверяется повторно. `review` не равен `accepted`. В браузерном профиле принятие — решение пользователя; в native-пути хост повторно читает своё задание и проверяет байты. Это не OS-независимый verifier. Браузерное локальное хранилище не защищено от самого владельца/DevTools или компрометации его профиля.

## ADR-I06 · Публикация пока только в отдельную новую копию

Нет записи обратно в исходный проект. UI экспортирует отдельные файлы/пакет; CLI и native source создают новую папку. Конфликты трёхсторонней публикации имеют отдельно проверенную функцию обнаружения, но не внедрённый транзакционный публикатор. Поэтому исходные K06/T04 не считаются закрытыми.

## ADR-I07 · Ограничения памяти не назвать квотой ОС

1 МиБ на файл, 8 МиБ/256 файлов на исходный набор, 64 МиБ логических сохранённых выходов графа, 500 узлов/1000 связей, 4096 событий запуска, 30 отображаемых запусков, 32 МиБ serialized UI state. Это лимиты данных приложения, не предел физической RAM процесса. Копии строк, сериализация, браузер и драйвер имеют дополнительную память. CPU/GPU квоты не реализованы.

## ADR-I08 · Версии и воспроизводимость

Проверено: Node 22.16.0, TypeScript 5.8.3. Нативная цель: Rust 2024/toolchain 1.99.1. Tauri 2 и ряд Cargo-зависимостей ещё разрешаются диапазонами; Cargo.lock отсутствует, так как Cargo недоступен. Не называть это воспроизводимой нативной сборкой или SBOM. Скрипт запрещает молчаливую генерацию lockfile без `-ResolveDependencies`.

## ADR-I09 · Не автоматизировать рабочий стол

Не запускались приложение, браузер, dev-server, GUI-тесты, модель или внешний агент. Production worker bundle испытан в Node VM как программа, не через браузерное управление. Визуальная/пользовательская приёмка открыта.

## Оставшиеся точные риски

- Native unsafe Win32/IPC код не скомпилирован и не подвергнут Windows fault-injection. Дескриптор текущего пользователя не отделяет враждебные процессы того же пользователя; такие процессы не допускаются этим профилем.
- Импорт папки проверяет тип/метаданные, но не является защищённым снимком при враждебных reparse/TOCTOU гонках.
- Нет полноценной процедуры undo внешнего эффекта или публикации; undo относится только к документу.
- Browser IndexedDB и native SQLite реализации не испытаны общим сквозным GUI-тестом.
- Native IPC-ошибка после start может означать принятый запуск. Нужно перечитать состояние; повтор с новым command ID не считается безопасной сверкой. В 0.2 outbox написан и его контракт испытан; сквозная IndexedDB/Tauri/Windows/Rust связка остаётся открытой.
- Родитель/дочерние работы, расписание, приоритетное управление под нагрузкой, защита от голодания и карантин реальной VRAM ещё не подключены.
- В 0.1 единая редакция документа также увеличивается при некоторых изменениях представления. Отдельное переиспользование семантической версии графа без layout-инвалидации ещё не реализовано; это консервативное лишнее устаревание, не изменение уже запущенного снимка.

## ADR-I10 · Команда до транспорта

Frozen intent записывается отдельно от UI-редактора; отправка только после commit. Сверка read-only. Тот же ID для доставки, новый для новой намеренной работы. Отказ хранилища или неизвестный протокол блокирует отправку.

## ADR-I11 · Принятие конкретного снимка

Binding соединяет run, исходную цель, версии и все artifacts. Решение владельца нельзя перенести на другой снимок. Native host перечитывает файлы; поздний worker не меняет terminal state. Это не изолированный verifier.

## ADR-I12 · Отмена и остановка различаются

COMMIT cancel_requested предшествует сигналу AtomicBool. SQL fence запрещает поздний review. Это не остановка произвольного дерева и не освобождение GPU.

## ADR-I13 · Exact bytes для команды

specJson передаётся как строка; SHA-256 вычисляется над её UTF-8 bytes, а не над заново сериализованными числами. Fingerprint возвращается в ответе и сверяется клиентом. Это не криптографическая подпись.

## ADR-I14 · SQL-стенд не равен Windows

Фактические SQL v1/v2 исполнены Node SQLite 3.49.1 с rollback journal. Native Store всё ещё требует >=3.51.3 перед WAL. Нативные callbacks, IPC, IndexedDB не участвовали. Golden fixture проверен TypeScript; Rust-половина пока только source.

## ADR-E01 · Переиспользование Studio и узкий нативный инструмент

Инкремент 0.4 продолжает `33291c9`, сохраняет 305 старых проверок. Новый модуль `native/tools/economy` — stdlib-only Go executable, не новое агентное ядро. Это **явное отклонение** от предпочтения писать всю системную часть на Rust: ядро Studio остаётся Rust, но для независимых локальных инструментов поставлен уже собранный Windows EXE. Go/Node/Python не требуются на пользовательском ПК. Не переписывать рабочие инструменты только ради языка; слияние с будущим Rust runtime решается по измеренной цене обслуживания.

Go 1.23.2 — фактически доступный компилятор стенда, не заявление о новейшей/рекомендуемой версии. Внешних Go modules нет. Обновление закреплённой toolchain до поддерживаемой версии и целевая Windows-проверка остаются обязательными перед распространением как стабильной сборки. LICENSE Go включён.

## ADR-E02 · Байты, токены и квота — три разные единицы

Собственный MCP ограничивает итоговую UTF-8 сериализацию до 24 КиБ, текст элемента — до 4 КиБ. Это локально проверяемые границы, но не точный токенизатор и не гарантия всего входа Codex. В токеновых полях собственного результата остаётся null. `model_context_window`/компактизация и поздний interrupt не переименованы в строгий pre-request fence.

## ADR-E03 · Не включать непроверенный шлюз вместо подписки

Опциональный HTTP/SSE gate имеет локально испытанный допуск явных запросов до отправки, конечное число запросов на task и unknown без автоматического повтора. Он отвергает неучтённую историю/модальности/opaque reasoning. Поэтому не включается молча в `launch`, не читает auth.json и не назначает недокументированный ChatGPT upstream. Совместимость полного Codex и охват всех его сетевых отправок не объявлены. Экономия квоты не измерена.

## ADR-E04 · Политика и захват

Встроенные инструменты читают данные и выполняют фиксированные Git-операции. Shell отключён в предложенном профиле; произвольные команды доступны не модели, а только вручную владельцу через capture либо заранее разрешённый check. Это ограниченный профиль исследования, не обещание полноценного coding-agent с произвольной сборкой. Обёртка процесса не sandbox. Отказ capture не подменяет exit code, потерянный ACK не разрешает retry, новые packet IDs не являются безопасным повтором неизвестного check.


## R05 · одно исполнение и одна task-БД

ResearchPlan — контракт исследования, не второй модельный цикл. diagnostic_sweep компилируется в существующий local_batch, владеет scope/preflight и сохранением наблюдений, но не решает гипотезы по коду0. 1–3 фрагмента — представление, оригиналы остаются в прежнем artifact store. Новая SQL v4 таблица нужна для атомарной связи immutable GoalRevision, последовательности и task progress; не отдельная база. Она закрыта от UPDATE/DELETE, поэтому откат старого бинарника требует отдельной backup-базы. Schema и CAS проверены независимо от недоступного Rust. Смысловые выводы различаются от наблюдений. Code Mode, новый router, embeddings и автономный LLM-наблюдатель не добавлены.
