# Интеграция 0.3 · Studio + Desk + Codex Direct

**10 ноября 2026. Исходники интеграционного инкремента; нативная сборка и первый живой Windows-маршрут не приняты.**

Основание: Platform Studio `46b4a415b1b6e21988de7c7332dac186959a09e0`, неизменённые исходные тесты Studio и Assistant Desk. Эта работа не создаёт новый репозиторий, универсальный исполнитель или модельный цикл.

## Граница функциональности

В живом профиле доступны написанные обработчики создания задачи и привязки папки, настройки пути Codex, открытия/продолжения сессии, отправки текста как написан, уточнения выбранного хода, прерывания, сверки, истории команд и наблюдения. В браузерном HTML без Tauri они честно недоступны; импорт JSONL остаётся самостоятельной локальной возможностью.

Унаследованный шестииэкранный Desk полностью сохранён в `assistant/`, включая 82 регрессии и собственный сценарный режим. В `assistant.html` подключены **четыре** рабочие поверхности: работа, наблюдение, история, подключения. Это не заявление о переносе всех шести экранов в живое исполнение. Файловая приёмка/слияние/публикация и команда на канвасе по-прежнему не закрыты живым профилем.

Codex Direct пока ограничен `read-only`; `workspace-write` есть в общей модели привязки, но нативный первый профиль его отклоняет. Передаются запрет расширения прав и отказ на неподдерживаемые запросы. В процесс явно передаются `features.computer_use=false` и `computer_use.default_app_access="deny"`. Эти параметры и read-only — **не доказательство** соблюдения всех ограничений конкретной версии: shell, ambient hooks/MCP, локальные настройки, права чтения и запрет запуска GUI требуют целевой проверки. Профиль не допускается к рабочим закрытым данным или недоверенным проектам до такой проверки. `cwd` не является песочницей.

Авторизация использует установленный Codex; приложение не извлекает auth.json, не копирует ключи и не запускает login автоматически. Нативный EXE выбирается явно; shell-шлюзы `.cmd` не запускаются. Настройка executable после рестарта хоста требует повторного подтверждения, автоматической установки нет.

## Точные изменения к предложенному плану

1. `in_flight` записывается **до** возможной первой записи в stdin. Завершение после fence, но до отправки консервативно оставляет unknown. JSON-RPC request ID не считается устойчивым idempotency key провайдера.
2. `unknown_needs_user_decision` не уничтожает возможность поздней сверки. Совпадение времени или текста ответа модели не подтверждает доставку. Используется точный пользовательский элемент с сохранённым nonce в ожидаемом треде; для steer — в ожидаемом ходе. Отсутствие элемента в ограниченной странице ничего не разрешает повторять.
3. Неотправленная команда может быть снята явно: SQL-транзакция и tombstone запрещают её запоздалую отправку, даже если IPC-запрос ещё не попал в таблицу. Для `in_flight`/unknown такой сброс запрещён.
4. Interrupt ACK подтверждает приём запроса, не остановку. Завершение хода наблюдается отдельно. Старые поколения не изменяют текущую сессию. Стартовый ACK не возвращает уже завершённый ход в running.
5. Rust не вызывает `control.ts` напрямую. Существующие pure-функции сохранены и испытаны, хранение task-level состояния подготовлено. **Автоматическая смысловая оценка прогресса/списание общего бюджета ещё не подключены к host**: успешный tool-call не используется как ложное доказательство продвижения. В первой версии нет автоматического цикла supervisor/retry, который обходил бы этот пробел.
6. Основание применимости проверки включает цель, критерии, артефакт, зависимости и область покрытия, не только `(turnId, workspaceHash)`. Поздняя несвязанная реплика не отменяет исторически проверенный снимок. Это код контракта, не действующий независимый verifier.
7. Поток в UI читается по курсору из локального журнала; таймер не вызывает модель. Неизвестные события остаются наблюдениями с ограниченным preview, а не молча превращаются в расход 0.

## Исполнение и наблюдение

Нативный host управляет отдельным Codex-процессом на сессию, до двух процессов в этом профиле. JSONL-кадр ограничен 4 МиБ, сохранённый preview — 256 КиБ, журнал сессии — 8192 события / 32 МиБ. Удаление старого диапазона видно через `prunedThrough`/gap. Граница и оборванный кадр закрывают соединение с unknown; универсального replay нет. **Это не полное сохранение каждого байта stdout команд.** stderr Codex дренируется, но содержимое сейчас не сохраняется; отдельный безопасный диагностический канал остаётся работой.

События получают часы приёма хостом, поэтому интервалы не выдаются за серверную очередь или сетевое время. Анализатор сохраняет разделение cumulative/response/delta, cache входит во входные токены, reasoning — в выходные. TTFT появляется только из поддержанного явного поля. Потерянные события, первая накопительная точка и отсутствие usage отмечаются. Получение ответа модели не означает приёмку результата.

История команд и подробные события локальны и могут содержать приватный контент. Маскирование известных структурных ключей не распознаёт все секреты внутри произвольного текста. Исходную БД нельзя автоматически публиковать; диагностический экспорт метрик отделён от полной истории.

## Что ещё не выполнено

- Сборка Rust/Tauri и разрешение зависимостей с проверенным Cargo.lock. Изначальные pins сохранены, совместимость не объявлена проверенной.
- Реальный Codex, установленная версия/схема, аккаунт, Windows named pipe и API-совместимость.
- Живой restart окна / смерть host / смерть Codex / сон ОС. Клиентский restart не равен падению сервиса.
- Проверка UI в WebView2, клавиатура, экранный диктор, доступность, реальные несколько окон и производительность.
- Принудительная изоляция, полные журналы команд, OTEL/hook-коллектор, строгая верхняя стоимость, semantic supervisor, исследовательские ветки, штатный change-review, публикация.
- Автоматическая расстановка правил для пользовательских hooks/MCP. Они остаются частью проверяемого профиля Codex, а не автоматически доверенными зависимостями.

Все 96 PF сохранены без объявления приёмки. Полный профиль G1/G2/G3 не закрыт. Наличие исходников `connect` не заменяет реального соединения.

## Ближайшая граница проверки без смены основы

На подготовленном Windows-стенде: проверить toolchain/lock, собрать core/host/desktop, прогнать native tests, подтвердить ограничения Codex Direct на разрешённом тестовом каталоге. Только затем — один согласованный модельный ход с подтверждённой версией, steer/interrupt и восстановление. Сначала фиксируется допуск на внешний вызов; аккаунт и содержимое проекта не выбираются скрыто.

Нужен именно этот прогон, не новый canvas, не переписывание модели и не возвращение OmniRoute в обязательную цепочку.

## Основания протокола

Официальные документы прочитаны 10.11.2026: https://learn.chatgpt.com/docs/app-server и https://learn.chatgpt.com/docs/config-file/config-reference . Они подтверждают описанные операции и параметры, но не совместимость нашей неподтверждённой нативной сборки. `thread/turns/list` используется вместо предположения, что `thread/read` всегда возвращает всю историю. `turn/steer` привязан к `expectedTurnId`. Актуальная версия установленного у владельца Codex неизвестна.
