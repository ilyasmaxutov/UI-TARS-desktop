# 0.4 · Локальные инструменты экономии

Основание: 33291c9. Не новая платформа; нет второй LLM и замены Codex inference loop.

Поставляется готовый Windows x64 `studio-economy.exe` и исходник Go/stdlib. Самостоятельный запуск MCP/CLI не зависит от незавершённой Rust-сборки. Добавлен профиль запуска уже установленного Codex без изменения глобальной конфигурации. Native host подключает тот же инструмент через stdio и показывает `modelInputHardLimit:false`, а не ложное «strict работает». Экраны и предметная модель 0.3 не переписаны.

Реализованы пакеты до32 операций, зависимости search→read_matches, ограниченная конкурентность, возобновление по сохранённым элементам, локальные файлы/поиск/диапазоны/метаданные/Git, отдельный лог stdout/stderr, инспекция середины и байтовых срезов, точный пакет продолжения без модельного пересказа. Источник не сериализуется целиком в проект. Полный вывод хранится локально; ответ ограничивается на выходе собственного инструмента. Одинаковая работа не требует постоянного модельного polling.

Опциональный gate: допускает только явно обозримые Responses HTTP/SSE-входы, сохраняет состояние до dispatch, не повторяет после неопределённого эффекта, сохраняет частичный ответ. Изменение policy не сбрасывает бюджет task. Нет автоматической интеграции с подписочным endpoint, WebSocket/opaque reasoning отвергнуты. Это проверенный ограниченный механизм, не полный строгий профиль Codex.

Сборки Windows EXE и Windows test binary выполнены; Windows binaries не запускались. Go/Linux race tests и прежние TS/SQL/DOM-fixture тесты выполнены. Никаких GUI, dev-server, пользовательского CODEX_HOME, аккаунтов, внешних моделей или сетевых провайдеров. HTTP-тесты используют только loopback-получатель.

Полная Windows-площадка, живой Studio↔Codex, точный pre-dispatch токеновый потолок всего Codex, автоматический смысловой supervisor, финансовый предел подписки и качество решения реальных задач остаются открыты. Подробнее: `verification/economy-0.4/REPORT.md`.
