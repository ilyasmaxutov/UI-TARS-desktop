# Отбор из result.json для Platform Studio

**Дата анализа:** 16 ноября 2026. **Исходный экспорт:** 394 сообщения (`messages[0..393]`) за 2 августа — 16 ноября; 283 с обычным текстовым полем, 9 с текстом в `rich_message`, ещё 102 без экспортированного текста (в том числе вложения Telegram, для которых медиафайлы не включены). Полный экспорт включает личные записи и технические конфигурации; **его нельзя автоматически импортировать в проект, внешние логи, открытые issue или модельную память**.

Это тематический отбор по задаче: улучшить стратегию исследований и отладки в Platform Studio, а не собирать общий каталог всех технологий. Ниже индекс записи относится к массиву `messages` исходного JSON. Утверждения канала — **данные поста**, а не гарантированная функциональность соответствующего проекта; ключевые источники сверены по ссылкам на репозитории/документы.

## Итог для ТЗ

Внедрять в порядке: **диагностическая стратегия → пакетный сбор свидетельств → связывание причинного вывода с сырьём → сохранение checkpoints → A/B пользы → опциональные адаптеры/самообучение**. Это решает проблему «модель по одной команде в каждом ходе» гораздо точнее, чем отдельный JS Code Mode без плана. Прямое принуждение *внутреннего* Codex к нужной стратегии возможно только если инструменты действительно проходят через управляемый интерфейс; с одним сторонним MCP Studio может только рекомендовать нужную стратегию и измерять соблюдение.
