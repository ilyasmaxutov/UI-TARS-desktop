# 0.5 · диагностические исследования поверх существующего исполнения

Основание: `3967b46d7b2e0e4b47ef4bdae98b6c01c415f378`. Ветка `research/diagnostic-sweep`.
Это инкремент исходников и локально испытанных компонентов, не принятая нативная Windows-студия.

## Поставлено

- `src/assistant/research.ts`: контракты ResearchPlan/Hypothesis/Probe/EvidenceRef/Report, preflight, связь с оригиналом задачи, ограниченный пакет продолжения, версионные выводы и контрдоказательства. Чистая политика использует прежний `recordCycle`.
- `native/tools/economy/research.go`: read-only `diagnostic_sweep`, компилируемый в прежний `local_batch`. Та же блокировка, тот же планировщик независимых/зависимых операций, те же каталоги packets/artifacts. Нет второй модели, MCP-сервера или БД.
- Полные наблюдения сохранены; в ответе не более трёх фрагментов и ограниченные ссылки. Перед чтением проверяются область, ссылки на гипотезы, зависимости, rootHash и pin-хэши, конечные пределы. Код 0 не переводит гипотезу в истину.
- Снимки источника до/после чтений, конечный бюджет хэширования; изменившийся источник, пропущенные файлы и неполная выдача видны. Это не атомарный снимок ФС и не ОС-песочница.
- `diagnosis-first.txt` действительно включается в MCP initialization и developer instructions существующего native Codex adapter. Простой запрос остаётся на `local_batch`. Правила не гарантируют поведение чужого внутреннего shell.
- `research_store.rs` + SQL v4: одна append-only таблица контрольных точек в существующей TaskStore-БД. Сырьё не копируется в SQL. Общий no-progress/sweep count относится к задаче. Фактический SQL проверен Node/SQLite; Rust методы не исполнялись.
- `research.rs` хоста: запуск того же helper, проверка запечатанного локального отчёта, чтение checkpoint и read-only reconcile; распознавание диагностического MCP completion. Неявного model turn или повторной отправки нет. Это source-only до Rust/Windows-проверки.
- Desk: вкладка «Исследование», старые и новые вопросы, альтернативы, покрытие, точные ссылки, авторские выводы и неизвестность. Импорт явно не удостоверяет подлинность. Проверены обработчики/шаблон, не компоновка в браузере.

## Реальные исправления в предыдущем исполнителе

1. Пустой поисковый запрос на пустом дереве возвращал успешный пустой результат. Теперь он отвергается до обхода.
2. После restart `read_matches` проверял размер сохранённого search-артефакта, но не хэш. Same-size подмена пути воспроизведена и закрыта проверкой SHA-256 до декодирования.
3. Изменившийся во время поиска файл без совпадений теперь делает покрытие неполным, а не отрицательным свидетельством.
4. Новый слой сохраняет `unknown` при сочетании признаков неизвестности и неполноты. Журнал сводки не может менять покрытие запечатанного отчёта.
5. Завершённый пакет 0.4 можно прочитать как прежний снимок; незавершённый пакет не запускается автоматически новым кодом после обновления.

6. Гонка WalkDir/atomic rename в учёте приватного хранилища закрыта ограниченным повтором полного измерения; исчезновение постоянного файла не игнорируется.
7. Неумещающиеся обязательные метаданные результата отклоняются на preflight до чтений.

## Принципиальные границы

Модель по-прежнему формулирует гипотезы и интерпретирует наблюдения; локальный код не угадывает первопричину по строке error. Структурная проверка плана не доказывает качество исследования.

Read-only означает набор разрешённых операций нашего инструмента, а не изоляцию любого процесса Codex. Существующий пользовательский shell/hooks/MCP могут жить вне этого маршрута. В standalone helper лимиты числа пакетов в плане — контракт для исполнителя; авторитетный межсессионный счётчик реализован в TaskStore/host и требует целевого испытания. Не выдавать наличие поля maxSweeps за запрет всех модельных продолжений.

Нативная стыковка записывает наблюдаемые отчёты. Структурированные смысловые Finding имеют проверенную TS-модель и импорт/просмотр; автоматическое сохранение произвольных свободных ответов живого агента как проверенных выводов не реализовано.

Сведения о выводе — UTF-8 байты, не токены. observedTokens=null означает отсутствие наблюдения; modelCalls=0 относится только к локальному инструменту. Нет заявления о жёстком потолке всех запросов Codex или процентах экономии.
