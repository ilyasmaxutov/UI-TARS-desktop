## Протокол 2 и восстановление

Команда проходит `prepared → sending → confirmed / unknown`. До успешной записи никакой отправки нет. `get_command` только читает. Новый ID не создаётся ради потерянного ответа. Новая намеренная работа, напротив, получает новый ID даже при одинаковом содержимом.

Хост получает `specJson`, считает SHA-256 точных UTF-8 bytes, сохраняет fingerprint вместе с командой и возвращает `commandFingerprint`. Это избегает предположения, что JavaScript и Rust одинаково сериализуют дробные числа. Ответ также сверяется по исходным входам, цели и идентичности документа. Это не подпись и не замена аутентификации канала.

Старый protocol=1 блокирует отправку. Подтверждённая команда, исчезнувшая из базы хоста, не воссоздаётся автоматически. При отказе IndexedDB нет перехода на RAM-хранилище. Outbox использует CAS редакций; лимиты — 64 записи, 64 МиБ. Неподтверждённые записи не удаляются ради новой команды.

## Принимается снимок, не сообщение

Binding включает run ID, document ID/hash, input hash, command fingerprint, graph/goal revisions, исходную цель и хэши всех артефактов. Дата и убедительность findings не являются основанием. Повторное принятие того же снимка идемпотентно; замена снимка требует новой проверки и решения.

Это проверка встроенных детерминированных критериев, не доказательство смысловой полноты запроса и не OS-независимый verifier. Экспорт остаётся отдельной копией, не публикацией в оригинал.

## Хранилище и совместимость

Миграции `v1.sql/v2.sql` выполняются в IMMEDIATE transaction с `user_version=2`. `run_controls` хранит отмену и binding принятия. Триггеры запрещают смену frozen spec, возврат terminal в running, review после отмены, перезапись принятого payload, отмену cancel-флага, изменение command/events.

Rust Store повторно читает frozen spec, проверяет критерии и артефакты перед принятием/экспортом. Исторический формат JSON-хэшей 0.1 распознаётся. Старый `accepted=true` без receipt требует явного нового принятия.

Перед испытанием миграции нужна копия каталога данных при остановленном хосте. Автоматическая backup/downgrade процедура ещё не реализована. 0.1 нельзя считать совместимым с user_version=2. SQL-пробы здесь не меняли пользовательскую базу.

## Воспроизведение

```powershell
npm install --ignore-scripts
npm run verify
node tools/check-recovery.mjs .\recovery-evidence
```

Последняя команда требует новую папку. Дочерний CLI-процесс завершается кодом 91 после COMMIT, до ответа; после открытия БД обнаружен один запуск, повторных dispatch при сверке — ноль. Это не отключение питания и не испытание Rust/Windows/IndexedDB.

На подготовленной Windows с установленным закреплённым Rust и отдельно проверенным Cargo.lock:

```powershell
.\scripts\Verify-Native.ps1 -Offline
```

Скрипт не устанавливает инструменты, не создаёт lockfile и не запускает GUI/browser/dev-server. Сохраняет причину блокировки и CLI-логи. Сам PowerShell-скрипт здесь не выполнялся. Cargo test/check не закрывают K01–K15.
